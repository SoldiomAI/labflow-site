Trust · Document 01

Security dossier

This page is written for the person who has to say "no" — the IT manager, the quality officer, the security reviewer. No marketing claims; every item below names the mechanism, what it protects against, and how you can check it yourself.

1 · The architecture is the security model

LabFlow is a desktop application. Your database lives in a folder on your own machine; multi-user deployments talk over your local network only. There is no cloud tenant, no vendor database, no telemetry endpoint. Most data-breach scenarios that apply to cloud LIMS — vendor compromise, credential stuffing against a hosted portal, subpoenaed third-party servers, silent terms-of-service changes — do not apply, because the surface they attack does not exist here.

Verify it: run the application with Windows Resource Monitor or any packet capture open. The application blocks its own outbound network traffic as policy; you will see no calls home — during install, activation, or daily use.

2 · Tamper-evident audit trail

Every significant action — logins, result entries, edits, approvals, exports, configuration changes — is appended to an audit log where each record carries an HMAC-keyed hash that chains to the previous record, similar in spirit to a blockchain ledger.

  • What it protects against: silent history rewrites — by anyone, including administrators editing the database file directly.
  • What happens on tampering: chain verification fails from the altered record onward, and the verification screen shows exactly where.
  • Verify it: Settings → Audit → Verify chain. Then try editing an old row in a throwaway database and verify again.

3 · E-signed results and certificates

Result approval applies a cryptographic e-signature tied to the approving user. Exported Certificates of Analysis carry the signature, so a printed or emailed certificate can be checked against the record that produced it.

  • What it protects against: forged or altered reports circulating under your laboratory's name.
  • Verify it: approve a result, export the CoA, alter a digit in a copy, and run verification — the altered copy fails.

4 · Licensing without an activation server

Licence keys are signed with Ed25519 and verified locally against your machine ID. Activation is a paste, not a connection.

  • What it protects against: the classic failure of activation servers — vendor goes away, server goes down, product stops working. LabFlow has no server to go down; a valid key keeps verifying offline, indefinitely.
  • Also worth knowing: the private signing key never ships in the product. Only the public verification key is embedded.

5 · Encrypted backups

One-click backups are encrypted before they are written to whatever destination you choose — USB drive, network share, external disk. Restoring requires the passphrase.

  • What it protects against: the most common real-world leak in small laboratories — a readable backup on a lost USB stick.

6 · Accounts, roles, and sessions

  • Passwords are stored as salted hashes, never in plain text.
  • Role-based access: administrator, supervisor, analyst, QA and reception see only what their role permits.
  • Failed-login lockout slows brute-force attempts on shared workstations.
  • Trial and licence state are anchored against clock rollback, so winding the system clock back does not extend anything.

7 · Supply chain: verify what you install

Every release is published with SHA-256 checksums and a software bill of materials (SBOM) listing the exact open-source components inside the installer.

# PowerShell — verify the installer you received
Get-FileHash .\LabFlow-Setup.exe -Algorithm SHA256
# compare against SHA256SUMS.txt from the release

8 · On ISO 17025 and regulatory language

Accreditation applies to laboratories, not to software, so we will never claim "ISO 17025 certified software" — no honest vendor can. What LabFlow provides are the controls an ISO 17025-minded assessment expects to find: attributable records, tamper-evident history, signed reports, calibration and maintenance logs, and access control. We are glad to walk your quality team through how each mechanism maps to your checklist.

9 · Disclosure

Found a security issue? Open a report on GitHub — or reach us through the contact section — and you will get a human reply. We publish fixes in the changelog and credit reporters who want credit.
